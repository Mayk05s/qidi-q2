# Состояние проекта и что дальше

Записано 2 ноября 2026. Как пользоваться панелью, описано в `README.md`.

## Работа сейчас

- Принтер QIDI Q2 с QIDI Box, адрес и пароль в `.env` (в git не попадает).
- `./setup.sh`: пункт 1 ставит модуль и панель на принтер, пункт 4 запускает панель на Mac. Агент запускает установку сам: `printf '1\ny\n' | ./setup.sh`. Скрипт берёт пароль из `.env`, агент его не читает и не вводит.
- Обновлять принтер можно только когда он не печатает.

## Проверено на железе

- Чтение меток Bambu и QIDI через считыватели Box, сохранение в слот.
- Панель внутри Fluidd и цвета в её панели материалов.
- Запись через ACR122U с подтверждением чтением (метка E83E2288).

## Написано, на железе не проверено

- Запись и поиск метки через считыватели Box: `BAMBU_RFID_TAG_READ`, `BAMBU_RFID_TAG_WRITE`, окно поиска на вкладке NFC. Проверено только на модели чипа и демо. Первый тест: чистая метка, катушки со считывателя убрать.
- Кнопка «Перечитать» после последней переделки.
- Кнопка «Открыть в QIDI Studio» из браузера. Сама ссылка проверена: Studio скачала файл по `qidistudioopen://<url>` с локального адреса.
- Какая версия сейчас на принтере, неизвестно: последние правки на него могли не попасть, нужен пункт 1.

- Учёт остатка на катушках: `SpoolUsage` в модуле, активный слот берётся из `box_extras.loaded_slot`, расход из `print_stats.filament_used`. На печати не проверен. Чтение общего номера катушки Bambu из блока 9 тоже: на случай неудачи есть запасной ключ по UID.

- Чтение слота мотором при заправленной голове: `BAMBU_RFID_SLOT_READ`. Проверено только на тестах. Мотор проверялся отдельно: 50 мм вперёд и назад на 1A с пустой головой. Покачивание: 100 мм назад и 50 мм вперёд, это покрывает примерно четверть оборота. Безопасная длина при заправленной голове не измерена, больше ставить только после теста.

- Проверка «Хватит ли пластика» (`box_patch/packages/usage/print_check.py`; блок над слотами панели убран, теперь показ во Fluidd): расход из файла, T → слот из `value_tN`, остаток по метке из `bambu_spool_usage`. Проверена на настоящих файлах и данных принтера, ход печати только в имитации. Не выяснено: кто меняет `value_tN`, если при отправке из Studio выбрать другие слоты, и какое имя файла в `print_stats` при настоящей печати. На реальной печати сверить разбивку «ещё нужно»: длины по T из G-кода расходятся со слайсером на несколько процентов (909 и 973 мм у T0).

- Проверка в QIDI Studio: `tag_writer/studio_check.py`, ставится `python3 -B tag_writer/install_studio_check.py` в `~/.qidi_studio_check`, профиль «0.20mm Standard + проверка пластика @Q2». Проверено только вне Studio. При первой нарезке выяснить: появляется ли профиль, запускается ли скрипт при нарезке, есть ли в его файле строка расхода, останавливает ли «Отменить» (код выхода 1) отправку. Журнал: `~/Library/Logs/qidi_studio_check.log`. После правки скрипта установку повторить. Кнопка перечитывания в окне зовёт `/api/slot_read` панели на принтере и на железе не нажималась.
- `filament_inventory` в Studio: ручной список катушек с процентом остатка, UID и облачной синхронизацией. Списания при печати и проверки перед печатью при разборе файлов программы не нашлось, в работе не проверялось.

- Выбор замены на случай, когда катушка закончится, не сделан. При окончании `runout_gcode` в `printer.cfg` вызывает закрытую команду `AUTO_RELOAD_FILAMENT` (включено, `auto_reload_detect = 1`), по её описанию в Studio она берёт катушку с теми же свойствами. Как она выбирает, неизвестно, повлиять на неё без изменения на принтере нельзя. Сначала нужен тест настоящего окончания на короткой печати.

- На 2 ноября 04:11 в слот 1B записана метка 7081205A от катушки 1A (считыватель общий), поэтому у 1B и 1A один ключ и один остаток. По словам пользователя, это след экспериментов: метка прочитана не в тот слот. Одна метка в двух слотах физически невозможна, значит, такая запись всегда ошибочна. Чтение мотором исключает метку соседа (`EXCLUDE`), штатное чтение в панели такого не передаёт, это вероятное место бага, не проверено. Проверка пластика такой повтор пока не замечает и считает остаток дважды. Панель теперь при «Перечитать» спрашивает, что делать, если метка уже есть в другом слоте (`same_tag`, `/api/slot_forget`, `skip_neighbour`). Проверено на поддельном принтере. Чтение при вставке филамента и кнопка в окне Studio этого окна не показывают.

- Учёт остатка теперь запоминает пару UID и номер катушки (`uids` в `spool_usage.json`), чтение без номера идёт в ту же запись. Старые записи связываются при первом чтении с номером. На принтере не проверено.

- Подсказка о нехватке пластика на экране принтера: `PrintWatcher` в `print_check.py`, работает в службе панели на принтере. При старте печати отправляет сообщение `RESPOND TYPE=error` с кодом `QDE_004_900` (не штатный) и русским текстом. В простое окно появилось и текст читается, во время настоящей печати не проверено: не остановит ли окно печать, и как быстро появится (команда ждёт в очереди G-кода). При старте, когда катушек хватает, сообщения нет.

- Что показывает экран принтера, проверено по одному в простое: `RESPOND TYPE=error` с кодом и без кода показывает окно; `M117`, `M118` и окно Klipper (`action:prompt`) не показывает.

- Окна экрана описаны файлами `/home/qidi/QIDI_Client/resource/qidi_client_error/QDC_*/N.json` (текст по языкам, тип, кнопки, поле `main_pic`, везде `NO_PIC`). Общее окно для сообщений Klipper: `QDC_100_005_000_001`. На каждый код есть скомпилированный обработчик в `qidiclient`, поэтому новый код файлом не добавить. Значки в окне 14×14, `access/error_popup/`. Откуда берётся номер `N`, не выяснено, картинка через `main_pic` не проверялась. Файлы принадлежат `qidi`, правка только через `sudo`, обновление прошивки может её стереть.

- Картинка в окне экрана: через `main_pic` штатного `QDC_100_005_000_001/0.json` появляется (проверено), но общая для всех ошибок этого окна. Отдельные папки окон со своими кодами экран не использует, показывает только текст. Решено оставить текстовое окно, штатные файлы не менять, тестовые файлы с принтера убраны.

- Окна экрана, разбор продолжается. Цвет текста окно не поддерживает: `#E53935` показался буквально, через ответ `!! Malformed command`. В программе есть окна для BOX 3 и 4 (`QDC_300_002_005_003`, `004` и другие); при одном Box они не нужны и могли бы стать окнами для пластика. Как они вызываются, проверяется: текст ошибки `BOX 4 temperature and humidity sensor abnormal…` отправлен на экран в простое. В программе также есть поля `_warning_msg`, `_warning_level`, `_warning_code` рядом с данными филамента файла и строка `prepare_to_print_warning`, не разобраны.

- Программа установки: `installer/` (окно SwiftUI, `qidi_backend.py`, сборка `build_app.py`), функции `bambu`, `nfc`, `spools`, `usage`, `mesh` передаются в `remote_setup.py --features`. Проверены тесты, чтение состояния настоящего принтера и логика на демо. Окно запускается, но его вид никто не проверял: снимок экрана был недоступен. Настоящая установка из программы ещё не запускалась.

- Быстрая печать: макрос `MESH_MACRO` в `remote_setup.py` заменяет `BED_MESH_CALIBRATE` из `klipper-macros-qd/KAMP_Settings.cfg`. Штатный макрос на принтере подтверждён: Y всегда полный, X не меньше 60–210, 4×6 точек минимум. Наш: модель 40 мм по центру даёт 4×5 при `keep_purge: 1` и 4×4 при `0` (проверено рендером, на печати нет). На первой печати сверить в консоли границы и что `EXCLUDE_OBJECT_DEFINE` идёт раньше `PRINT_START`: иначе замер будет полным. Обновление прошивки может стереть блок, тогда применить ещё раз.

- Окно «мало пластика» на экране: при старте печати служба панели рисует картинку катушки с номером слота (`plastic_picture.py`, `slot_font.json` из `make_slot_font.swift`), пишет текст в окна BOX 3 (красное) и BOX 4 (оранжевое), перезапускает программу экрана через `qidi-screen-reload.path` и вызывает окно командой модуля `BAMBU_SCREEN_WARNING`. Штатные файлы этих окон сохраняются в `/home/qidi/qidi_panel/screen_stock`, откат их возвращает (`box_patch/packages/usage/screen_popup_setup.py`). Если окно не вышло, остаётся текстовое сообщение. Проверено вручную в простое, не установлено, на печати не проверено: главный вопрос, не мешает ли перезапуск экрана при старте печати. На принтере лежит старая копия штатных окон `/home/qidi/qdc_plastic_backup`, после установки её можно удалить.

- Остаток в Fluidd: `box_patch/packages/usage/fluidd_card.py`, скрипт грузится из `qidi_panel_link.js` с панели (`/fluidd_card.js`, данные `/api/fluidd`). Под каждой катушкой в «Управлении материалами» граммы с полоской, под карточкой своя карточка «Остаток пластика» с предупреждением для идущей печати или последнего файла. Проверено только на макете страницы с настоящими данными принтера, в настоящем Fluidd не проверено. Встроенный способ Fluidd это Spoolman: компонент есть в Moonraker, но нужен отдельный сервер Spoolman, не ставили. Проверка в QIDI Studio удалена с Mac по просьбе пользователя, файлы `studio_*` в проекте остались.

- Пакеты rfid_core, bambu, nfc, panel и usage разложены по папкам `printer/`, `tests/`, `tools/`. Общий модуль разделён: запись меток ушла в `nfc/printer/bambu_nfc.py` (секция `[bambu_nfc]`), учёт остатка и окно экрана в `usage/printer/bambu_spool_usage.py` (секция `[bambu_spool_usage]`); опции `spool_usage` в секциях считывателей больше нет. Тесты проходят, на принтере после разделения не проверено: что Klipper загружает оба новых модуля, команды записи меток появляются у считывателей, учёт остатка идёт при печати и окно BOX 3 и 4 вызывается.
